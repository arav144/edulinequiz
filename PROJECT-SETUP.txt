PROJECT STRUCTURE
-----------------
Quiz-System/
├── frontend/          ← Student Portal (Next.js 14, English-only, Responsive)
├── backend/           ← Express API + MongoDB Atlas + Admin Panel at /admin
└── PROJECT-SETUP.txt  ← This file

ARCHITECTURE
------------
frontend/   = Student quiz portal. Complete student registration with email OTP,
              strict class-wise quiz access, 40s/question timer, English UI,
              and instant Result/Certificate PDF downloads.
backend/    = Express REST API + MongoDB + Admin SPA at /admin route.
              Handles OTP generation & verification, class-wise filtering,
              1 student = 1 attempt enforcement, server-side grading,
              and PDFKit Result/Certificate PDF generation.

The Admin Panel lives at: backend/public/admin/ (static SPA served by Express)
Students access: http://localhost:3000
Admins access:   http://localhost:5000/admin

STUDENT AUTHENTICATION & QUIZ API ROUTES
-----------------------------------------
POST   /api/auth/send-otp               ← Send 6-digit OTP to student email
POST   /api/auth/verify-otp             ← Verify 6-digit OTP -> return verificationToken
POST   /api/auth/register               ← Submit student details & receive JWT token
GET    /api/auth/me                     ← Get authenticated student profile
GET    /api/quizzes/available           ← List quizzes filtered by student class
GET    /api/quizzes/:id/start           ← Start quiz (enforces class eligibility & 1 attempt)
POST   /api/quizzes/:id/attempt         ← Submit answers, grade server-side, record attempt
GET    /api/results/:id                 ← Get attempt result & score breakdown
GET    /api/results/:id/pdf             ← Download Result Report PDF (No dates/times)
GET    /api/results/:id/certificate     ← Download Passing Certificate PDF (No dates/times)
GET    /api/admin/students              ← List all registered students (Admin only)
GET    /api/admin/students/:id          ← Get student detail & attempt history (Admin only)    /api/admin/quizzes/:id           ← Update quiz (admin)
DELETE /api/admin/quizzes/:id           ← Delete quiz (admin)
GET    /api/admin/questions             ← All questions (admin)
POST   /api/admin/questions             ← Add question with image/audio (admin)
PUT    /api/admin/questions/:id         ← Update question (admin)
DELETE /api/admin/questions/:id         ← Delete question (admin)
POST   /api/admin/upload/image          ← Cloudinary image upload (admin)
POST   /api/admin/upload/audio          ← Cloudinary audio upload (admin)
DELETE /api/admin/upload/asset          ← Delete asset from Cloudinary (admin)
POST   /api/admin/subjects              ← Create subject (admin)
PUT    /api/admin/subjects/:id          ← Update subject (admin)
DELETE /api/admin/subjects/:id          ← Delete subject (admin)
GET    /api/admin/attempts              ← All student attempts (admin)
GET    /api/admin/attempts/:id          ← Attempt details (admin)

STUDENT FLOW
------------
1. Open http://localhost:3000
2. See available published quizzes with subject badges
3. Enter Candidate ID and Name to access quiz
4. Answer MCQ questions (A/B/C/D) with optional image & audio support
5. Submit — one attempt per student per quiz (enforced at DB level)
6. View immediate Pass/Fail results with percentage & passing threshold
7. Download Official Result Summary PDF (A4 Portrait)
8. If passed, download Official Completion Certificate PDF (A4 Landscape)

================================================================================
  DATABASE (MONGODB ATLAS)
================================================================================

COLLECTIONS
-----------
quizzes    ← Quiz metadata (name, subjectId, numberOfQuestions, passingPercentage, status)
questions  ← MCQ questions (question, options A-D, correctAnswer, imageUrl, audioUrl, subjectId, quizId)
attempts   ← Student submissions (unique compound index: { studentId: 1, quizId: 1 })
subjects   ← Subject taxonomy (name, slug, description)

IMPORTANT CONSTRAINTS
---------------------
- Compound unique index on attempts: { studentId: 1, quizId: 1 }
  This strictly prevents duplicate attempts at the database engine level.
- Questions are MCQ (4 options: A, B, C, D).
- Quizzes are status-gated: Published quizzes are accessible to students; Draft and Closed cannot be attempted.
- Single-page Quiz & Question builder in Admin: Questions are authored and updated directly inside the Quiz modal.
- Answer keys are NEVER sent to the student frontend during the quiz.
- Media assets (images & audio) are hosted on Cloudinary CDN.
- PDFs are generated dynamically on the server using PDFKit.

  DEPLOYMENT (VERCEL)
================================================================================

BACKEND DEPLOYMENT
------------------
1. Push backend/ folder to a GitHub repo
2. Import to Vercel
3. Set environment variables in Vercel dashboard:
   - MONGODB_URI
   - JWT_SECRET
   - FRONTEND_URL (your Vercel frontend URL)
   - ADMIN_USERNAME
   - ADMIN_PASSWORD
   - CLOUDINARY_CLOUD_NAME
   - CLOUDINARY_API_KEY
   - CLOUDINARY_API_SECRET
   - NODE_ENV=production
4. Deploy — backend/vercel.json is already configured

FRONTEND DEPLOYMENT
-------------------
1. Push frontend/ folder to a separate GitHub repo
2. Import to Vercel
3. Set environment variable:
   - NEXT_PUBLIC_API_URL=https://your-backend.vercel.app
4. Deploy

IMPORTANT: Frontend and Backend are deployed as INDEPENDENT Vercel projects.
